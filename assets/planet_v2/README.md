# Planet model — v0.9.50

Ferron now has a Blender terrain mesh with broad basalt basins, eroded highlands,
craters and canyon detail. Ferron is the live planet in Kessler. The other five
planet appearances remain available in the asset loader, with their established
colors and an ice cap on Glacia, for the zones Claude has shelved.

## Assets

- `planet.blend`: editable, packed Blender source with a Cycles sun-lit preview scene.
- `planet.glb`: 146,688 triangles, PBR textures embedded, about 27.3 MB.
- `planet.data.js`: identical GLB as a script fallback for direct-file play or failed binary downloads.
- `textures/surface_albedo.jpg`: 4096 × 2048 base color, JPEG quality 96.
- `textures/surface_normal.png`: 4096 × 2048 lossless tangent-space normal map.
- `textures/surface_roughness.png`: 2048 × 1024 roughness source (packed into the GLB material).
- `source/imagegen_surface.png`: original 1774 × 887 image from the built-in ImageGen tool.
- `source/imagegen-prompt.json`: exact generation prompt and provenance.
- `source/imagegen_surface_detail.png` and `source/imagegen-detail-prompt.json`: refined ImageGen source and exact edit prompt.
- `previews/`: Blender render, before/after game views, and all zone appearances.
- `preview.html`: interactive Ferron model viewer; drag to orbit and scroll to approach.

Blender combines the reconstructed ImageGen color source with new fine crater
rims and regolith grain, baking 4K material maps in continuous 3D coordinates.
The ImageGen tool itself returned a 1774 × 887 source; the additional detail is
generated by Blender at bake resolution. The runtime adds the existing
ImageGen-derived asteroid regolith at a second scale to maintain surface grain
on approach, using up to 16× anisotropy. These two extra textures are embedded
in the GLB as the auxiliary `Planet_Detail` material; no extra network requests
or temporary blob dependencies are needed in the game.
The mesh has 2.25 times the triangles of the first model, and the color and normal
maps have four times its pixels. The larger download is cached once per session.
No rendered day/night terminator or emissive light is baked into the material.
The thin atmosphere uses an inexpensive sun-facing limb approximation, not a
volumetric atmosphere simulation.

## Runtime behavior

The existing planet remains visible until the asset is ready. If both loading
paths fail, the procedural planet remains playable. Every zone retains its
radius, gravity, collision shell, resource metadata and orbit configuration.
The highest terrain is at 1.002501 times the nominal radius, inside the existing
1.006 collision shell. Planets remain scenery and cannot be mined or landed on.

Geometry and textures are cached once for the session. Zone-specific materials
are released when a planet is removed; pending loads cannot revive an old zone.
The planet receives the game's solar lighting and eclipse treatment but does
not enter the small local shadow map as a caster.

## Rebuild and validation

Run Blender 5.2 with `-b -t 8 -P assets/planet_v2/build_planet.py`, then
`node assets/planet_v2/package_asset.cjs`.

`node tests/planet-integration.cjs http` checks the actual game, all active zones,
day/night rendering, the collision envelope, texture readiness, shared-resource
lifetime, and rapid zone changes. Modes `file`, `script`, `invalid`, and `missing`
exercise direct-file loading and error recovery. Results include the exact game
SHA-256; visual captures use deterministic game state and the existing sun.
All five loading modes passed on the final v0.9.50. The existing lighting regression also
passed with unchanged mining behavior, local shadows and planet eclipses; its
report and captures are saved in `lighting-regression/`.

The integration was initially tested on v0.9.48 across all six planet appearances,
then reconciled with Claude's `a8e2524` map commit and `46864bd` density commit.
The final patch preserves the Kessler-and-Hub chart, denser belts, revised rock
size distribution, manual Hub refueling and repair-parts storage.
It retains UTF-8 BOM and CRLF. `change-proof.json` records the latest base commit,
the immediate pre-edit backup hash, and every HTML replacement.
